rules_riviera

rules_riviera

Bazel rules for Aldec Riviera-PRO, a mixed-language (Verilog / SystemVerilog / VHDL) HDL simulator.

The public surface is four rules over three providers:

  • riviera_library — compile a verilog_library / vhdl_library DAG into ONE self-contained Riviera library.
  • riviera_hdl_testbench — package an HDL testbench top for elaboration.
  • riviera_cocotb_testbench — package a Python cocotb testbench (auto-locates libcocotbvpi_aldec.so, wires the VPI).
  • riviera_sim_test — elaborate + simulate a testbench under vsimsa. Cocotb-agnostic — only reads RivieraTestbenchInfo.
  • riviera_toolchain — bind the eight Riviera executables (vsimsa/vsim/alib/alog/acom/asim/vmap/acdb) to the toolchain type the rules resolve.

Everything else — coverage collection under bazel coverage, //tools/acdb2lcov for ACDB -> lcov conversion — is designed around those rules.

Setup

Riviera-PRO is a commercial simulator; this repo does not distribute it. rules_riviera provides the Bazel rules and the toolchain type contract — how Riviera actually reaches your Bazel actions is deployment infrastructure and lives entirely in your own repo.

MODULE.bazel

bazel_dep(name = "rules_riviera", version = "0.1.0")

register_toolchains("//tools/riviera:my_riviera_toolchain")

Author a toolchain

Bind vsimsa and acdb (mandatory) to executables that resolve to the corresponding Riviera binaries. The ideal is a hermetic toolchain that vendors the install into the Bazel action graph; how that install is actually provisioned is up to you.

# tools/riviera/BUILD.bazel
load("@rules_riviera//riviera:riviera_toolchain.bzl", "riviera_toolchain")

riviera_toolchain(
    name = "my_riviera_toolchain_def",
    acdb = "//path/to:acdb",
    vsimsa = "//path/to:vsimsa",
    requires_network = True,   # set True when the license server is remote
    version = "2025.04",
)

toolchain(
    name = "my_riviera_toolchain",
    toolchain = ":my_riviera_toolchain_def",
    toolchain_type = "@rules_riviera//riviera:toolchain_type",
)

Rules

Four public rules, three providers. Every rule is single-purpose and speaks one provider — no rule holds "am I in cocotb mode?" state.

RuleProducesConsumes
riviera_libraryRivieraLibraryInfoVerilogInfo / VhdlInfo

Anything that produces RivieraLibraryInfo (pre-built vendor library, imported UVM archive, etc.) is a drop-in for the testbench rules' library attr; anything that produces RivieraTestbenchInfo is a drop-in for riviera_sim_test.testbench. No sim-rule surgery required to accommodate new sources of either provider.

  • riviera_library — compile a verilog_library / vhdl_library DAG into one Riviera library.
  • riviera_testbench — two rules: riviera_hdl_testbench (SV/VHDL top drives DUT) and riviera_cocotb_testbench (Python drives DUT via VPI). Both feed riviera_sim_test.
  • riviera_sim_test — elaborate + simulate a testbench under vsimsa. Automatic coverage under bazel coverage.
  • riviera_toolchain — bind Riviera executables to the toolchain type consumed by the rules above.

riviera_library

load("@rules_riviera//riviera:riviera_library.bzl", "riviera_library")

riviera_library(name, deps, srcs, compile_opts, defines, exec_requirements, jobs, library_name)

Compile the full transitive HDL DAG into ONE self-contained Aldec Riviera library.

deps takes verilog_library / vhdl_library targets (anything providing VerilogInfo or VhdlInfo). The rule walks the whole reachable source graph — own srcs + hdrs, transitive .deps, and cross-language .vhdl_deps / .verilog_deps — and compiles it in one alib/alog/acom invocation via a generated vsimsa .do script. Output is one TreeArtifact directory; downstream consumers (testbench rules, riviera_sim_test) vmap it by the logical library name.

srcs is an optional escape hatch for HDL files that only make sense inside this Riviera library (a Riviera-specific stub, a compile-time wrapper) and don't warrant their own HDL-library target.

Runs through //tools/riviera_wrapper so vsimsa's HOME is isolated per-action (~/.aldec/ doesn't bleed into the user's real home) and stdout is buffered — nothing streams unless the action fails or a # Error/# Fatal slips past vsimsa's exit code.

Users compose library boundaries by wiring multiple riviera_library targets together via other consumers, not by cross-linking riviera_library deps.

riviera_cocotb_testbench

load("@rules_riviera//riviera:riviera_testbench.bzl", "riviera_cocotb_testbench")

riviera_cocotb_testbench(name, deps, library, module, top)

A cocotb testbench — top is the HDL DUT, module is the Python cocotb test module that drives it via VPI.

Produces RivieraTestbenchInfo with every cocotb-specific derivation resolved at testbench-definition time:

  • top_unit — the unqualified unit name for cocotb's TOPLEVEL env.
  • cocotb_toplevel_lang — derived from library.language (mixed defaults to verilog; override via the sim rule's env attr).
  • vpi_lib — the libcocotbvpi_aldec.so located inside deps runfiles; the sim rule injects -pli <path> into asim.

Also provides PyInfo (merged from deps via py_venv_common) so riviera_sim_test can pull the whole Python graph into its own venv with one create_dep_info call. When cocotb loads embedded Python via the VPI shared object, that Python sees cocotb in its sys.path.

riviera_hdl_testbench

load("@rules_riviera//riviera:riviera_testbench.bzl", "riviera_hdl_testbench")

riviera_hdl_testbench(name, library, top)

A plain HDL testbench — top is a SystemVerilog / VHDL module that drives the DUT and calls $finish / std.env.finish.

Produces RivieraTestbenchInfo with cocotb_module="" and vpi_lib=None. riviera_sim_test reads that provider and elaborates <library>.<top> under vsimsa; the HDL testbench itself terminates the simulation.

Splitting cocotb and HDL into two rules — instead of one rule with an optional-cocotb attr — keeps every attr on each rule always-applicable and moves the "am I in cocotb mode?" decision to testbench-definition time rather than sim-invocation time.

riviera_sim_test

load("@rules_riviera//riviera:riviera_sim_test.bzl", "riviera_sim_test")

riviera_sim_test(name, data, env, exec_requirements, generics, jobs, sim_opts, testbench)

Elaborate + simulate a Riviera testbench under vsimsa as a Bazel test.

Takes exactly one testbench — either an riviera_hdl_testbench or an riviera_cocotb_testbench, both of which provide RivieraTestbenchInfo. The rule is oblivious to the HDL-vs-cocotb distinction: everything cocotb-specific (the -pli VPI path, MODULE / TOPLEVEL / COCOTB_TOPLEVEL_LANG env, merged Python PyInfo) is packaged inside the testbench provider and forwarded verbatim.

Rule ↔ launcher hand-off:

  1. The rule builds a ctx.actions.args() bundle describing everything the launcher needs (tool rlocation keys, library name, top, generics, sim opts, coverage flag, cocotb config) and writes it to a multiline param file via ctx.actions.write(content = args).
  2. It exposes exactly one env var — RIVIERA_ARGS_FILE_RLOC — whose value is the args file's runfiles-library key.
  3. The launcher (//tools/riviera_launcher) reads the env, resolves the args file via runfiles.Rlocation, argparse's it, resolves every *_rloc field to an absolute path, constructs the .do at runtime, and hands vsimsa the absolute path.

Coverage kicks in automatically under bazel coverage via ctx.coverage_instrumented(): the launcher adds -coverage sbceam -acdb to the .do, renders html + text into $TEST_UNDECLARED_OUTPUTS_DIR, and converts text → lcov via //tools/acdb2lcov for $COVERAGE_OUTPUT_FILE.

riviera_toolchain

load("@rules_riviera//riviera:riviera_toolchain.bzl", "riviera_toolchain")

riviera_toolchain(name, acdb, acom, alib, alog, asim, env, jobs, requires_network, version, vmap,
                  vsim, vsimsa)

Declares an Aldec Riviera-PRO toolchain by binding one executable per Riviera tool.

Each tool attr takes an executable target that resolves to the corresponding Riviera binary. In the ideal case that's a hermetic toolchain that vendors the whole install into the Bazel action graph; in practice it can be anything Bazel can exec — the toolchain only cares that each attr resolves to something that behaves like the named tool.

Load-bearing tools — invoked directly across the Bazel action boundary, so their attrs are mandatory = True:

  • vsimsa — every riviera_library compile action and every riviera_sim_test launcher call.
  • acdb — invoked by riviera_sim_test's launcher during bazel coverage post-processing.

Discoverability tools — vsim, alib, alog, acom, asim, vmap — run inside vsimsa's TCL interpreter today and never cross the Bazel boundary. Exposed here so future rules or downstream consumers have a place to bind if they ever need a Bazel-visible path to those binaries.

acdb2lcov

A pure-Python tool that converts Aldec's acdb report -xml output to lcov .info format. Usable independently of the Bazel rules — the same code powers riviera_sim_test's coverage post-processing.

Where it lives

  • Binary: //tools/acdb2lcov:acdb2lcov — a py_binary (from @rules_venv//python:py_binary.bzl) with the CLI entrypoint. py_binary also exposes the module for direct import by any downstream py_binary / py_test / py_library that depends on it. Mypy walks the sources directly via the aspect, so downstream consumers get inline type-hint checking without extra opt-in.

Python usage

from acdb2lcov import parse_acdb_xml, emit_lcov

xml = open("coverage_report.xml").read()
report = parse_acdb_xml(xml)
open("coverage.info", "w").write(emit_lcov(report.files))

to_json / from_json handle serde-style round-trips through dataclasses.asdict + json.dumps — handy for persisting coverage across pipeline stages without re-parsing the XML.

CLI usage

bazel run @rules_riviera//tools/acdb2lcov:acdb2lcov -- \
    --input coverage_report.xml --output coverage.info

Both flags take filesystem paths.

Format notes

Riviera exposes coverage as acdb report -xml <acdb> -o <out.xml>. The XML schema Aldec ships isn't publicly documented; parse_acdb_xml walks a best-effort mapping:

<coverage>
    <file path="/abs/path/to/foo.sv">
        <statement line="10" hits="5"/>
        <branch line="11" block="0" branch="0" hits="0"/>
    </file>
</coverage>

If a Riviera release changes the element / attribute names, adjust _iter_file_coverage in tools/acdb2lcov/acdb2lcov.py — every parser change stays local to that function.

Coverage types beyond <statement> and <branch> (Covergroup, Expression, Condition, FSM, Toggle, Assertion, Path) are silently skipped — they're not representable in lcov and the launcher's flow doesn't ask acdb to emit them.
