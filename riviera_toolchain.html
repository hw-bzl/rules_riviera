riviera_toolchain

load("@rules_aldec_riviera//riviera:riviera_toolchain.bzl", "riviera_toolchain")

riviera_toolchain(name, acdb, acom, alib, alog, asim, env, jobs, requires_network, version, vmap,
                  vsim, vsimsa)

Declares an Aldec Riviera-PRO toolchain by binding one executable per Riviera tool.

Each tool attr takes an executable target that resolves to the corresponding Riviera binary. In the ideal case that's a hermetic toolchain that vendors the whole install into the Bazel action graph; in practice it can be anything Bazel can exec — the toolchain only cares that each attr resolves to something that behaves like the named tool.

Load-bearing tools — invoked directly across the Bazel action boundary, so their attrs are mandatory = True:

  • vsimsa — every riviera_library compile action and every riviera_sim_test launcher call.
  • acdb — invoked by riviera_sim_test's launcher during bazel coverage post-processing.

Discoverability tools — vsim, alib, alog, acom, asim, vmap — run inside vsimsa's TCL interpreter today and never cross the Bazel boundary. Exposed here so future rules or downstream consumers have a place to bind if they ever need a Bazel-visible path to those binaries.
